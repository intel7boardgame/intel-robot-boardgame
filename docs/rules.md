## 1. 윷놀이 (본 계획)

### 기본

- 플레이어: 사람 1명(또는 관객 팀) vs 로봇
- 말: **편마다 2개**. 처음에는 모두 자기 대기 칸에 있습니다
- 선공: 사람
- 승리: 말 2개를 모두 먼저 내보낸(완주한) 편

### 윷 결과

윷가락 4개를 던져 **평평한 면(앞)이 위로 온 개수**로 정합니다.

| 앞 개수 | 결과 | 이동 | 한 번 더 |
|---|---|---|---|
| 1 | 도 | 1칸 | |
| 2 | 개 | 2칸 | |
| 3 | 걸 | 3칸 | |
| 4 | 윷 | 4칸 | ✅ |
| 0 | 모 | 5칸 | ✅ |

- **낙:** 윷가락이 트레이 밖으로 나가거나 4개가 다 인식되지 않으면 벌칙 없이 다시 던집니다.
- **빽도:** MVP에서는 쓰지 않습니다 (정할 것 참고).

### 윷판과 칸 이름

29칸입니다. 바깥 20칸은 `cell_0`~`cell_19`, 지름길은 `diag_*`, 가운데는 `center`입니다.
말은 시계 반대 방향(오른쪽 위로 올라감)으로 돕니다.

```
 cell_10 ─ cell_9 ─ cell_8 ─ cell_7 ─ cell_6 ─ cell_5     ← cell_5: 모,  cell_10: 뒷모
   │  diag_l1                                diag_r1  │
 cell_11      diag_l2                  diag_r2     cell_4
   │                     center                       │
 cell_12      diag_r3                  diag_l3     cell_3
   │  diag_r4                                diag_l4  │
 cell_13                                           cell_2
   │                                                  │
 cell_14                                           cell_1
   │                                                  │
 cell_15 ─ cell_16 ─ cell_17 ─ cell_18 ─ cell_19 ─ cell_0     ← cell_15: 찌모, cell_0: 참먹이(출발·도착)
```

> 그림은 연결 관계만 나타냅니다. 실제 배치(정사각형, 모서리 사이 4칸)는 D가 도안으로 정합니다.

| 경로 | 칸 순서 |
|---|---|
| 바깥길 | 대기 → cell_1 → … → cell_19 → cell_0(참먹이) → 완주 |
| 모 지름길 | cell_5 → diag_r1 → diag_r2 → center → diag_r3 → diag_r4 → cell_15 → cell_16 … |
| 뒷모 지름길 | cell_10 → diag_l1 → diag_l2 → center → diag_l3 → diag_l4 → cell_0 → 완주 |

판 밖 슬롯: `wait_human`, `wait_robot`(대기 칸, 말 2개까지), `goal_human`, `goal_robot`(완주한 말), `yut_tray`(윷 트레이), `yut_cup`(로봇 윷통).

### 이동 규칙

1. **지름길:** `cell_5`(모)나 `cell_10`(뒷모)에 **멈추면** 다음 이동은 대각선으로 갑니다. 지나가기만 하면 바깥길로 갑니다.
2. **방(center):** `center`에 멈추면 다음 이동은 참먹이 쪽(`diag_l3`)으로 갑니다. 모 지름길로 `center`를 지나가기만 하면 그대로 `diag_r3` 쪽으로 갑니다.
3. **완주:** 참먹이(`cell_0`)를 **지나가야** 완주입니다. 참먹이에 딱 멈추면 다음 차례에 도 이상이 나오면 완주합니다.
4. **한 번 더:** 윷·모가 나오거나 상대 말을 잡으면 한 번 더 던집니다. 나온 결과는 모아 두었다가, 던지기가 끝난 뒤 원하는 순서로 하나씩 말에 적용합니다.
5. **새 말 올리기:** 대기 칸의 말도 결과를 적용해 판에 올릴 수 있습니다 (대기 칸에서 도 = `cell_1`).

### 잡기

- 이동을 마친 칸에 **상대 말**이 있으면 잡습니다. 잡힌 말(업혀 있었다면 모두)은 상대 대기 칸으로 돌아갑니다.
- 잡으면 **한 번 더** 던집니다.
- 잡힌 말 치우기: 로봇이 잡으면 로봇이 사람 말을 `wait_human`으로 옮기고, 사람이 잡으면 사람이 로봇 말을 `wait_robot`으로 옮깁니다.

### 업기

- 이동을 마친 칸에 **내 말**이 있으면 업습니다. 업힌 말은 이후 한 몸으로 움직이고, 잡히면 함께 대기 칸으로 갑니다.
- 업힌 말은 위아래로 끼워 두어 로봇이 한 번에 집습니다 (D가 끼움 구조로 출력).
- 업기는 선택이 아니라 같은 칸에 멈추면 자동으로 됩니다.

### 사람의 말 선택

- 결과를 적용할 말은 사람이 화면(키보드·버튼)에서 고르고, 직접 옮깁니다. 비전이 목표 칸을 확인합니다.
- 로봇은 전략 모듈이 고릅니다. MVP 우선순위: 잡을 수 있으면 잡기 → 업을 수 있으면 업기 → 완주에 가장 가까운 말 전진 → 새 말 올리기

### 실패 처리

- 윷 인식·말 이동이 2번 다시 해도 안 되면 화면 안내에 따라 사람이 처리(말 옮기기, 결과 입력)하고 이어서 진행합니다.

### 규칙 엔진 테스트 케이스 (C1 검증용)

| # | 상황 | 결과 | 기대 |
|---|---|---|---|
| 1 | 로봇 말 대기 | 도 | `cell_1` |
| 2 | 말 `cell_3` | 개 | `cell_5`에 멈춤, 다음 이동은 지름길 |
| 3 | 말 `cell_5` | 걸 | `cell_5`→diag_r1→diag_r2→`center` |

### 정할 것 (Day 1 회의)

- [ ] 빽도 사용 여부 (윷가락 하나에 표시 → 그 하나만 앞이면 1칸 뒤로). MVP 제외 제안
- [ ] 참먹이 완주 방식 (지나가야 완주 / 도착만 해도 완주). 지나가야 완주 제안
- [ ] 한 번 더 연속 횟수 제한 여부 (시연 시간 단축용) → 시뮬레이션상 시간이 줄지 않음, 제외 제안 (`docs/prep-notes.md` 3절)
- [ ] 한 판 시간 목표 20분 확인 (말 2개 기준) → 로봇 이동 25초 가정 시 평균 19.5분·46%가 20분 초과. Day 2 실측 후 `scripts/sim_yut.py`로 재확인

## 2. 돌 vs 인간 (차선책, Day 6 전환 시)

> 코리아보드게임즈의 퀴즈 보드게임 「돌 vs 인간」 규칙 틀을 참고했습니다. 원작은 상자에 든 돌을 흔들어 돌의 답을 정하지만, 팀 버전은 **로봇이 돌 편**을 맡아 주사위로 답합니다. 원작 문제 카드는 쓰지 않고 문제는 팀이 직접 씁니다.

### 핵심

- 모든 문제의 정답은 **숫자 0, 1, 2 중 하나**입니다. 보기를 고르는 문제가 아니라 "~는 몇 개일까요?"처럼 답이 숫자인 문제입니다.
- 사람은 알거나 추리해서 답하고, 돌은 무작위로 답합니다. 사람도 모르면 찍을 수밖에 없어서 돌에게 질 수 있다는 것이 재미 요소입니다.

### 기본

- 플레이어: **돌(로봇)** vs **인간(관객 팀)**. 편마다 말 1개
- 말판: 편마다 출발 칸 + **3칸** (`race_robot_0`~`race_robot_3`, `race_human_0`~`race_human_3`)
- 승리: **3칸을 먼저 이동한 편** (3문제를 먼저 맞힌 편)

### 한 라운드

1. **출제:** 화면이 문제 은행에서 문제 하나를 띄우고, LLM 진행자가 읽어 줍니다.
2. **인간의 답:** 관객끼리 의논해 0·1·2 중 하나를 외치면 진행자가 입력합니다.
3. **돌의 답:** 로봇이 주사위를 굴리고, 비전이 읽은 숫자(0·1·2)가 돌의 답입니다. 인간이 답을 정한 뒤에 굴려 서로 영향을 주지 않게 합니다.
4. **정답 공개:** 화면에 정답과 짧은 해설을 띄우고, LLM이 결과를 중계합니다.
5. **이동:** 맞힌 편의 말을 로봇이 1칸 옮깁니다. 둘 다 맞히면 둘 다, 둘 다 틀리면 아무도 움직이지 않습니다.
6. 어느 편도 3칸에 닿지 않았으면 다음 문제로 넘어갑니다.

> 돌은 라운드마다 1/3 확률로 맞히므로 3칸까지 평균 9라운드쯤 걸립니다. 사람이 절반 이상 맞히면 대개 5~6라운드 안에 끝납니다.

### 문제 작성 규칙 (C2)

- 정답은 반드시 0·1·2 중 하나. 세 숫자가 골고루 정답이 되게 씁니다 (한 숫자에 몰리면 찍기가 유리해짐).
- 문제마다 짧은 해설을 붙입니다 (정답 공개 때 화면·중계에 사용).
- 주제: 일반 상식, 프로젝트에 쓰인 기술(AI·로봇·윷놀이), 시연 장소 관련 문제. 너무 쉬운 문제와 아무도 모를 문제를 섞습니다.
- LLM은 문제 초안만 돕고, **정답은 반드시 사람이 검수**합니다.
- 원작 문제 카드를 옮겨 쓰지 않습니다.
- 형식(제안): `{"question": "...", "answer": 0, "explain": "..."}`

예시 (팀 작성):

| 문제 | 정답 | 해설 |
|---|---|---|
| 윷놀이에서 '모'가 나왔을 때 평평한 면이 위로 온 윷가락은 몇 개일까요? | 0 | 넷 다 둥근 면이 위면 모 |
| 윷놀이에서 '개'가 나왔을 때 평평한 면이 위로 온 윷가락은 몇 개일까요? | 2 | 평평한 면 2개가 개 |
| 이 게임에서 돌 편의 답을 정하는 주사위는 몇 번 굴릴까요? | 1 | 라운드마다 한 번 |

### 정할 것

- [ ] 0·1·2 주사위: 0·1·2가 두 면씩 적힌 주사위 출력 (권장, 인식이 단순) / 일반 주사위 눈을 3으로 나눈 나머지
- [ ] 둘이 같은 라운드에 3칸에 닿으면: 무승부 / 연장 문제 1개
- [ ] 인간 답 입력: 진행자 키보드 (MVP) / 음성 인식 (확장)
- [ ] 문제 수: 한 판 최대 약 10문제 × 시연 횟수 → 최소 50문제
